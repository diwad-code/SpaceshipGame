Recommended skills/packages for the SpaceshipGame repository
Analysis date: 2026-05-18

SOURCES REVIEWED
- SpaceshipGame repo: README, docs/ARCHITECTURE.md, docs/SCOPE.md, docs/COPILOT_WORKFLOW.md, .github/skills/*
- ComposioHQ/awesome-codex-skills: README plus selected SKILL.md files
- diwad-code/bmad-module-game-dev-studio: README, docs/reference/*, and the gds-create-game-brief / gds-gdd / gds-game-architecture / gds-investigate workflow areas

STARTING OBSERVATIONS
- SpaceshipGame is still in Sprint 0: there is no src/ tree and no package.json yet.
- The game repo already has two local skills: scaffold-scene and scaffold-system.
- We should not port BMad runtime wiring 1:1; we should only adapt the intent into lightweight prompts, skills, and durable docs.
- From awesome-codex-skills we should only add skills that complement our game-specific assets instead of duplicating current prompts/agents.

==================================================
1. PRIORITY: ADAPT FROM diwad-code/bmad-module-game-dev-studio
==================================================

1) game-brief package
   Target form: prompt + doc package, not necessarily a pure skill
   Why:
   - establishes a stable game brief before full code scaffolding starts
   - fits the current Sprint 0 stage very well
   Target location:
   - .github/prompts/game-brief.prompt.md
   - docs/GAME_BRIEF.md
   Priority: VERY HIGH

2) gdd package
   Target form: prompt + doc package
   Why:
   - organizes the main Game Design Document
   - gives later scene/system/data work a stable design reference
   Target location:
   - .github/prompts/gdd.prompt.md
   - docs/GDD.md
   - optionally docs/EPICS.md
   Priority: VERY HIGH

3) mechanika-spec
   Target form: real local skill
   Why:
   - matches the existing mechanika/ folder perfectly
   - helps create or refine one mechanic spec at a time without drifting the whole project
   Target location:
   - .github/skills/mechanika-spec/SKILL.md
   Priority: VERY HIGH

4) architecture package
   Target form: prompt/doc package
   Why:
   - deepens architecture decisions after the brief and GDD are stable
   - will help before larger Phaser/Vite/PWA scaffolding work
   Target location:
   - .github/prompts/architecture.prompt.md or equivalent
   - docs/ARCHITECTURE.md extensions
   Priority: HIGH, BUT AFTER brief + GDD + mechanika-spec

5) investigate package
   Target form: lightweight prompt or diagnostic skill
   Why:
   - useful later for debugging code, CI, and unfamiliar subsystems
   - too early right now because the repo still has no src/ tree
   Target location:
   - .github/prompts/investigate.prompt.md or a lightweight skill
   Priority: MEDIUM / LATER

==================================================
2. PRIORITY: SKILLS FROM ComposioHQ/awesome-codex-skills
==================================================

1) skill-creator
   Why it is valuable:
   - best bootstrap for creating and refining our own local skills
   - directly supports the plan to adapt BMad assets into .github/skills/
   - helps keep SKILL.md, references/, scripts/, and assets/ in a solid format
   Priority: VERY HIGH
   Decision: TAKE IT

2) webapp-testing
   Why it is valuable:
   - once Vite/Phaser/PWA code exists, it gives us a practical UI and regression-testing workflow
   - fits future scene, overlay, and PWA verification work
   Priority: HIGH, BUT ONLY AFTER THE APP EXISTS
   Decision: TAKE IT LATER

3) gh-fix-ci
   Why it is valuable:
   - once GitHub Actions exist, it will help diagnose and fix CI failures quickly
   - fits future build/test/PWA workflow checks
   Priority: HIGH, BUT ONLY AFTER CI EXISTS
   Decision: TAKE IT LATER

4) changelog-generator
   Why it is valuable:
   - useful for PWA/Android release notes and readable product change summaries
   - supports ongoing changelog maintenance well
   Priority: MEDIUM/HIGH
   Decision: TAKE IT

5) codebase-migrate
   Why it is valuable:
   - useful later for bigger migrations and mass refactors
   - overkill today, but potentially useful after the repo grows
   Priority: MEDIUM / LATER
   Decision: TAKE IT ONLY WHEN THE REPO IS LARGER

6) content-research-writer
   Why it is valuable:
   - can help with larger documentation packages: GAME_BRIEF, GDD, mechanika, ADRs
   - mainly useful for long-form research-heavy documentation work
   Priority: MEDIUM
   Decision: OPTIONAL

==================================================

- template-skill
  Reason: too bare; skill-creator is much stronger.

- skill-share
  Reason: depends on Slack/Rube and adds little value at the current stage.

- issue-triage / linear / notion-spec-to-implementation / connect / connect-apps
  Reason: require external integrations and processes we have not confirmed for this project.

- file-organizer
  Reason: more useful for personal filesystem cleanup than for this game repo workflow.

- deploy-pipeline / sentry-triage / pr-review-ci-fix / mcp-builder
  Reason: too early for the current Sprint 0 state.
